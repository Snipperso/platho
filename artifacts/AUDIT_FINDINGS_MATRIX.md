## Notes

- `UNFT-01` is distinct from the earlier M37 overpay cap. M37 prevents oversized public resend values above `20_000_000` nanotons, but does not make failed/no-pending resend refundable.
- `VCAP-01` was fixed in Vault, not by making ACK bounceable. The tombstone uses the existing `pending_publishes` map with `session_id == 0`, so it does not add a new persistent map or increase external publish pre-accept gas.
- `CAPHUB-02` was closed by canonical caps plus economics evidence, not by reverting to hash-only delivery. This is sandbox evidence for configured v1 cells, not a live-chain fee oracle.
- `VATH-01` is intentionally a basechain-only fix, not full cross-workchain support. Mainnet runbooks and PWA flows should treat ATH user paths as basechain-only unless workchain-aware envelopes are implemented later.
- `VATH-02` is closed at the ATHWallet notification state-machine layer because Vault alone cannot safely distinguish a late duplicate notification from a second real transfer once the official wallet forgets the original pending id.
- `BATH-02` is deployment/config scope, not a PWA user flow. It is intentionally enforced in release verification instead of adding unsupported-workchain policy to BuybackBurn `init`.
- `UNSEAM5-01` follows the same policy as `BATH-02`: deployment/config scope, enforced by final genesis verification rather than extra runtime code in UsernameRegistry.
- `SESSION-VAULT-01` intentionally does not promote `maxCharge > canonical` or raw manual overpay to findings. Those are governed by PWA pricing/signing policy and the standing rule that contracts should not grow runtime code purely to protect manual misuse when official PWA flows stay consistent.
- `SESSION-VAULT-01` carried seam items are verification items, not confirmed bugs. They should become findings only if the dedicated seam/deployment pass proves a real under-backed or under-refunded path in an official PWA or release flow.

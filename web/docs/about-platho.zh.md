# 关于 Platho

Platho 是一款通讯应用，面向那些不再愿意为基本数字生活——消息、身份、个人资料、历史记录以及对自有资金的访问——依赖他人基础设施的人们。

普通的互联网被建造得太过舒适，却只是对那些掌控它的人而言。账户可以被关闭。访问可以被限制。历史可以被删除。规则可以在用户已经把部分生活迁入某个平台之后被更改。在那里，用户不是所有者。用户只是一个租客，只在平台允许的时间内存在。

Platho 正是为反对这种模式而构建。

Platho 中的核心操作以用户的钱包为锚，并通过开放的智能合约来执行。钱包始终是控制的根源，而日常的应用活动可以通过 Vault 和已签名的命令来运行，无需每次都直接暴露钱包。这并不能让系统变得完美。它消除的是普通平台的核心缺陷：那种暗中改写规则、切断访问或夺取本应属于用户之物的隐藏能力。

私密消息以加密的胶囊条目形式锚定在链上。沉重的加密正文被承载于已被接受的 TON 交易正文中，从已被接受的 TON 交易历史中恢复，并对照 CapsuleHub 哈希进行校验，因此可用性取决于服务提供方的历史覆盖范围以及用户本地的加密缓存。公开消息、个人资料和名称使用可验证的合约状态，而非封闭的数据库。这减少了对服务器、运营方以及本周恰好方便的某项政策的依赖。

Platho 并不掩饰这种架构的代价。区块链是公开的。操作需要花钱。用户的失误可能是不可逆的。丢失的助记词无法通过客服找回，而且 Platho 不是永久的存档：紧凑的胶囊条目在保留窗口之后可能被修剪，而旧正文的取回则取决于服务提供方的历史或用户的本地缓存。这是一个艰难的模式。

个人钱包与 Vault 是分离的。钱包始终是控制的根源：它存入和提取资金，并掌控密钥。Vault 是介于钱包与公共网络之间的一层保护性合约。用户把有限数量的 GRAM/ATH 转入 Vault，而发布、协议支付以及其他应用操作则通过内部余额和已签名的命令来运行。这减少了钱包在链上的直接暴露，并限制了暴露给日常应用活动的价值量。

ATH 是协议的实用型代币。它用于用户名、头像更新以及空投后的协议手续费折扣。它的作用与应用内部的实际使用绑定。

ATH 是为系统参与者设计的。供应量中相当大的一部分是通过用户活动分发的，而非通过对早期地址的封闭式分配。这使得经济体较少依赖于狭窄的持有者群体，而更多地与真实的网络使用相连接。

Platho 对用户余额没有任何隐藏的管理性控制。这些合约不会赋予任何人一个任意的管理员开关，去攫取他人的资金、改写余额、暂停用户操作或升级协议规则。V1 仍保留有狭窄且已记录在案的启动期权限：创世绑定与封印、上池后的 BuybackBurn 路由冻结、上池后的 MarketStabilitySeller 定价冻结，以及预检之后单向启用的 FeeAccumulator 回购分账。

要点很简单：数字生活不应取决于平台的许可。在真实系统所能做到的范围内，消息、用户名、个人资料和资金都应尽可能地属于用户。

Platho 并不试图成为一个舒适的牢笼。它试图成为这样一种工具——让对基本数字事物的控制权回归到使用它的人手中，而不是回归到那些掌控服务器、数据库或访问规则的人手中。

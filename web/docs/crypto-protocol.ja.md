# Platho の暗号

## 鍵と本人性

すべては一つのシードフレーズから導かれます。ウォレットの鍵、署名の鍵、暗号化の鍵、走査の鍵です。秘密の側が端末を離れることはありません。サーバーは知りません——そもそもサーバーが存在しないからです。ネットワークも知りません。

チェーンへ出るのは公開側だけで、あなたの KeyShard に置かれます。そのシャードのアドレスはあなたのウォレットのアドレスに結び付いており、したがってそのウォレットが登録したものしか収められません。このアドレスによる結び付きが認可のすべてです。保存されるのは四つの項目——暗号化鍵、署名鍵、走査鍵、そして鍵世代の番号です。

鍵の識別子は割り当てられるのではなく、**計算されます**。`keyId = H(暗号化鍵, ML-KEM 鍵のハッシュ)`。他人の keyId を名乗るには、その人の暗号化鍵が要ります。

有効化とは、自分の公開鍵を初めて公開することです。費用は 0.06 GRAM、ウォレットから支払われます。

## 最初のコンタクト

見知らぬ相手への最初の一通は、共有の秘密に頼れません——まだ存在しないからです。そこで専用の経路を通ります。

**受け手はどうやって見つけるか。** カプセルの公開部分は 42 バイト。乱数の点 `R` と、2 バイトの目印 `view_tag` です。この目印は `R` と受け手の**走査**鍵から計算されます。受け手は最近のエントリをたどり、自分の鍵で目印を確かめます。外から見る者にはランダムなバイト列しか見えず、その手紙が誰宛てかを言い当てることはできません。受け手のアドレスは公開部分にそもそも含まれていません。

**受け手はどうやって差出人を確かめるか。** 暗号化された本体にはハンドシェイクが入っています。差出人による署名が、両者の keyId、差出人の静的な暗号化鍵、その ML-KEM 鍵のハッシュ、二つの KEM 暗号文、`R`、`view_tag`、そして使い捨ての番号——これらを束ねた転写に対して付されています。署名の検証は、どの項目かを信用する**前に**行われます。さもなければ、攻撃者は他人の署名を自分の鍵素材に接ぎ木できてしまいます。

確認は二つで足り、どちらもチェーンの読み取りを必要としません。

1. 提示された鍵から `keyId` を計算し直し、名乗られたものと一致しなければなりません。
2. 確認タグが、差出人が**同じルート鍵を導いた**ことを証明します。それには暗号化鍵の背後にある秘密が要ります。

一つ目は偽造者に被害者の鍵を使わせ、二つ目がまさにそこで捕らえます。ルート鍵は導けず、タグは合わず、その手紙は拒否されます。

バイト単位で同一の再送は、ハンドシェイクの使い捨て番号で見破られます。

最初のコンタクトの記録はチェーン上に一週間残ります。読まれるには十分で、記録庫になるには足りない長さです。

## 確立された会話

最初のコンタクトのあと、二人は共通のルート鍵を持ちます。以後のやり取りはすべて第二の経路へ移り、そこでは当事者について何一つ語られません。

```
K_root  = HKDF( X25519(a,B) ‖ ML-KEM-768 共有秘密,  info = ROOT ‖ 小さいほうの keyId ‖ 大きいほうの keyId )
K_epoch = HKDF( K_root,  info = RATCHET ‖ エポック番号 )
bucket  = HKDF( K_epoch, info = BUCKET ‖ 方向 ‖ エポック番号 )
```

ルート鍵はハイブリッドです。古典的な X25519 と、真に乱択された ML-KEM-768 のカプセル化の双方が入ります。耐量子強度とはこのことで、X25519 だけを狙う量子計算機ではこのルート鍵は破れません。

エポックは UTC の一日です。会話の各方向は**それぞれ固有の**不透明な `bucket` に書き込みます。これを計算できるのはルート鍵を知る者だけです。カプセルの公開部分は 40 バイトで、そこにあるのはこの `bucket` のみ。差出人も、受け手も、直前のメッセージへの参照もありません。索引を作ろうとする観測者に見えるのは一様乱数の 32 バイトで、誰とも結び付けられません。

## カプセル

本体は X25519 と ML-KEM-768 のハイブリッドで暗号化され、その上に認証付き暗号がかかります。差出人の本人情報（署名鍵、プロフィール版数、アバターの指紋）は公開部分ではなく暗号文の**内側**にあります。

カプセルの大きさは 1 KB から 32 KB までの固定の階級です。サイズは切り上げられるため、エントリの長さからメッセージの長さは分かりません。それを超える分は複数のカプセルに分割されます。

## 公開フィード

公開の投稿とコメントは**暗号化されません**——それが目的だからです。PublicShard に平文で置かれ、コントラクトはトランザクションの送信者を著者とみなすため、著者のウォレットは見えます。

コメントは別のシャードに置かれ、そのアドレスは投稿の座標から導かれます。

## 支払い

仲介者はいません。クライアント自身が外部メッセージに署名し、自分のウォレットから支払います。リレーも、内部残高も、公開を拒めるような信頼された第三者も存在しません。

プロトコル手数料はカプセル一つにつき 0.01 GRAM で、最初のコンタクトでも会話でも同額です。公開費用の残りは、ガスと保存に対してネットワークが課す分です。

## 復旧

会話の鍵は、端末から出ることのない鍵の下で端末に保存されます。これは再読み込みには耐えますが、再インストール後には役に立ちません。そこで二つ目の控えがあります。ルート鍵の一覧は**シードフレーズから導いた鍵で**封じられ、あなたの RecoveryShard のスロットに置かれます。シードフレーズだけを持つ新しい端末がそのスロットを見つけ、読み出し、復号すれば、会話は戻ってきます。

スロットに入れるのは、もう一度導き直せないものだけです。

## 何が守られ、何が見えるか

正直な一覧です。これがなければ、どんな約束もさほどの値打ちを持ちません。

**守られるもの:**

- 私的なやり取りの内容——読めるのはあなたと相手だけです。
- 私的なメッセージの宛先——受け手はステルス宛先指定と不透明な `bucket` に隠れます。
- 「誰と誰がやり取りしているか」の関係——ルート鍵なしに二つの方向を互いに結び付けることはできません。

**誰にでも見えるもの:**

- あるウォレットが私的なカプセルを公開したこと、その時刻、そしてサイズ階級。
- 公開されたものすべて——本文、画像、コメント、そして著者のウォレット。

## チェーン上の保存期間

| 対象 | 期間 |
|---|---|
| 最初のコンタクト | 1 週間 |
| 私的なやり取り | 1 年 |
| 公開の投稿とコメント | 1 年 |

期限を過ぎると、その記録はシャードから掃き出されます。それを公開したトランザクションはチェーンの履歴に無期限で残ります。ブロックチェーンでデータを削除することはできません。

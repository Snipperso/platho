# ATH ホワイトペーパー

## Platho プロトコルのトークン

ATH は Platho のユーティリティトークンです。活動報酬、エアドロップ終了後のプロトコル手数料の割引、`.ath` ネーム、アバターの更新、市場安定化のための売却、買い戻しと焼却に用いられます。

ATH は管理用トークンではありません。残高を書き換える、操作を止める、追加発行する、利用者の持ち物を変更する——そうした権限は一切与えません。その役割は、アプリの経済を動かし、Platho を使うという行為をオンチェーンの記帳に結び付けることです。

本書は Platho における ATH のモデルを説明します。

## 主要パラメータ

ATH の総供給量は固定です。

```text
100,000,000 ATH
```

ローンチ時の参照価格：

```text
1 ATH = 0.001 GRAM
```

ローンチ時の完全希薄化評価額：

```text
100,000,000 ATH * 0.001 GRAM = 100,000 GRAM
```

ATH は `100,000 GRAM` の参照時価総額から出発します。

## 固定供給

ATH は `ATHMaster` コントラクトが発行します。初期化時に `ATHMaster` は総供給量を `100,000,000 ATH` に固定します。

ジェネシス後の増発関数はありません。`ATHMaster` は管理者による鋳造、一時停止、ブラックリスト、送金税、強制送金、緊急引き出しのいずれも実装していません。

初回の発行は `DeployTreasurySupply` によって一度だけ行われ、供給の全量をトレジャリーの ATH ウォレットへ送ります。ジェネシスの発行を繰り返すことはできません。

総供給量は焼却によってのみ減ります。`ATHMaster` が焼却を受け入れるのは、所有者アドレスの決定的な ATH ウォレットから認証済みの焼却通知が届いたときだけです。検証を経て `ATHMaster` は `total_supply` を減らし、`ATHBurnFinalized` を送ります。

ATH の焼却は総供給量の実際の減少であり、使われないアドレスへの送金ではありません。

## 供給の配分

ATH の供給は四つの区分に配分されます。

| 区分 | 割合 | 数量 |
| --- | ---: | ---: |
| 活動エアドロップ | 15% | 15,000,000 ATH |
| 初期流動性 | 15% | 15,000,000 ATH |
| 長期プロトコル権利確定 | 10% | 10,000,000 ATH |
| 市場安定化準備 | 60% | 60,000,000 ATH |

この配分が Platho の経済構造を定めます。

- 供給の 15% は、プール公開の前に、アプリ内の活動を通じて利用者へ配られます。
- 供給の 15% は初期流動性に充てられます。
- 供給の 10% は変更不能な長期権利確定に固定されます。
- 供給の 60% は MarketStabilitySeller に入れられジェネシスで固定され、プール後の価格凍結を経てローンチ価格を上回る階層で売却されます。

最終ジェネシスにおいて、活動エアドロップと長期権利確定の準備は AirdropPool と ATHVesting の公式 ATH ウォレットによって裏付けられ、リリース検証器が本番リリース前にこれらの残高を確認します。`60,000,000 ATH` の市場安定化準備は MarketStabilitySeller に入れられ最終ジェネシスで固定され、その公式売り手 ATH ウォレットによって裏付けられます。検証器は本番リリース前にこの裏付けも確認します。準備は当初から満たされていますが、プールが公開されるまで売却されません。公開時に、証拠に紐づく一度きりの価格凍結が階層の基準価格を定めます。

## 長期プロトコル権利確定

長期権利確定の準備は次のとおりです。

```text
10,000,000 ATH
```

これは変更可能なトレジャリーの区画ではなく `ATHVesting` に保持されます。スケジュールはコントラクトに固定されています。

```text
100,000 ATH per 365-day period
100 periods
10,000,000 ATH total
```

ATH が確定した後は誰でも支払い請求を起動できますが、受益者は変更できません。コントラクトには加速、受益者の変更、一時停止、管理者による引き出し、緊急退避、裁量による解放のいずれもありません。

最終ジェネシスにおいて、公式の `ATHWallet(owner = ATHVesting, master = ATHMaster)` はちょうど `10,000,000 ATH` を保持していなければなりません。検証器はさらに、ローンチ前に請求済み ATH がゼロであること、休止フェーズであること、保留中の送金がないことを求めます。

この準備は意図して遅くしてあります。ローンチ時に 1000 万 ATH の流動的な塊を市場の上に置くことなく、プロトコル開発のための長い時間軸をつくるためです。

## 活動エアドロップ

活動エアドロップの総額：

```text
15,000,000 ATH
```

公開が成功したときの報酬：

```text
10 ATH
```

受理されたカプセル一つにつき、送った本人に `10 ATH` が入ります。どの経路でも同じです。公開に失敗した試行には何も入りません。

支払いはカプセルごとではなく、まとめて行われます。一回の配布には約 `0.0166 GRAM` の固定の、取り戻せない費用がかかり、その費用は配布が何 ATH を運ぶかに左右されません。カプセルごとに支払えば、そのカプセルが集めるプロトコル手数料より多くの費用がかかります。だから報酬は貯まってから、一度の支払いで届きます。

エアドロップは `AirdropPool` の公式 ATH ウォレットによって裏付けられており、その `15,000,000 ATH` はそこに置かれています。使い切れば、活動報酬は止まります。

## 活動の価格

メッセージは現在の基本価格から始まります。

```text
0.0191 GRAM
```

ATH 割引前の現在の正確な数値：

```text
プライベートメッセージ： 0.0191 GRAM
最初のコンタクト：       0.0178 GRAM
公開投稿：               0.0203 GRAM
```

公開が成功するたびに受け取れるのは：

```text
10 ATH
```

ローンチ時の参照価格で計算すると：

```text
10 ATH * 0.001 GRAM = 0.01 GRAM
```

これにより初期の ATH 配布がアプリの実際の利用と結び付きます。報酬は活動に対するボーナスであって、返金でもキャッシュバックでも割引でもなく、ATH が公開の GRAM 費用を埋め合わせるという約束でもありません。`10 ATH` の参照価値がカプセルの GRAM 費用を下回ることはあり得ますし、それは意図的です。利用者は実際の利用によってネットワークの初期の持ち分を得るのであって、保証された補償を得るのではありません。

カプセルの価格：公開投稿は `0.0203 GRAM` から、プライベートカプセルは `0.0191 GRAM` から。公開・プライベートを問わず大きなカプセルブロックほど高くなります。選ばれた本体が 1、2、4、8、16、32 KiB のいずれかであることが、シャード内の実行と保存の引当を変えるからです。報酬はカプセルの大きさによらず、正常に確定したカプセル一つにつき `10 ATH` のままです。

プライベートな公開は既定でハイブリッドのセキュリティ構成を用います。X25519 + ML-KEM-768 + AES-GCM です。プライベートメッセージに、より安価な従来方式のモードはありません。

公式のプールができれば、ATH は参照価格より高くも安くも取引され得ます。活動報酬は投資収益でも、利益の期待でも、価格の保証でもありません。

## プロトコル手数料と利用者価格

プロトコル手数料は、利用者が負担する総費用とは別のものです。

プロトコル手数料：

| 公開の種類 | プロトコル手数料 |
| --- | ---: |
| 公開投稿 | 0.010 GRAM |
| ハイブリッドのプライベートメッセージ | 0.010 GRAM |

利用者価格は、プロトコル手数料、ガス、そして記録をシャードに置くための保存原資を含みます。

| 公開 | 添付額 |
| --- | ---: |
| プライベートメッセージ | 0.0191 GRAM |
| 最初のコンタクト | 0.0178 GRAM |
| 公開投稿またはコメント | 0.0203 GRAM |
| アバターの更新 | 0.0395 GRAM |
| アカウントの有効化 | 0.0600 GRAM |

クライアントは常に二つの額のうち大きいほう——シャードの作成に必要なほう——を添えます。余剰は失われません。シャードは必要な分だけを残し、残りを送信者に返します。ネットワークの見積もりが想定より高く返ってきた場合、クライアントはその上に余裕を上乗せします。それは支払いではなく余裕であり、これもまた返ってきます。ATH の割引はプロトコル手数料に適用され、ネットワーク費用や保存引当には適用されません。

## ATH の割引

ATH は、活動エアドロップが完全に配り終わったあとに、メッセージのプロトコル手数料を下げます。

割引が解錠されるのは、残りの活動エアドロップが次の値になったときだけです。

```text
airdrop_remaining_ath == 0 ATH
```

それまでは、プロトコル手数料は全額支払われます。

全額割引のしきい値：

```text
10,000 ATH
```

自分の ATH ウォレットの残高が `10,000 ATH` 以上であれば、Platho 手数料部分について全額割引の段に達します。ネットワーク費用と保存引当は引き続き支払われます。

`10,000 ATH` を下回ると、手数料は直線的に下がります。

```text
raw_discounted_fee = ceil(full_fee * (10,000 ATH - min(user_ath_balance, 10,000 ATH)) / 10,000 ATH)
discounted_fee = raw_discounted_fee
```

計算は切り上げです。現在の定数では、完全なプロトコル手数料は公開・プライベートいずれのカプセルでも `0.010 GRAM`（`10,000,000 nanotons`）であり、最大の減額はカプセルあたり `0.010 GRAM` です。

## プールの公開

ATH/GRAM プールは、`15,000,000 ATH` の活動エアドロップがすべて配り終わったあとに公開されます。

公開の手順：

1. 利用者が Platho の実際の利用を通じて ATH を受け取る。
2. 活動エアドロップがすべて配布される。
3. ATH の割引が解錠される。
4. ATH/GRAM プールが公開される。
5. プール後の経路証拠と価格証拠が凍結される。
6. 買い戻しの分配が有効化される。

プールは参照価格から始まります。

```text
1 ATH = 0.001 GRAM
```

初期流動性の割り当て：

```text
15,000,000 ATH
```

ローンチ価格での GRAM 側：

```text
15,000,000 ATH * 0.001 GRAM = 15,000 GRAM
```

プール公開前に集めたプロトコル手数料が、初期流動性の GRAM 側を全額まかないます。これは立ち上げの一部であり、活動報酬を GRAM 建ての債権に変えるものではありません。

プールは、すでにアプリの利用を通じて配布済みのトークンを中心に公開されます。それが、利用者基盤のない空の上場と ATH を分ける点です。

## FeeAccumulator

GRAM のプロトコル手数料は `FeeAccumulator` に集められます。

買い戻しの分配が有効になる前は、蓄積された GRAM はすべてトレジャリーの区画へ移ります。

```text
accumulated_ton -> treasury_due_ton
```

分配が有効になるまで `buyback_due_ton` は増えません。

`EnableBuybackSplit` のあとは、蓄積された GRAM が分けられます。

```text
50% -> treasury_due_ton
50% -> buyback_due_ton
```

ナノトン単位の額が奇数の場合、余りは買い戻し側に残ります。

```text
treasury_amount = floor(amount * 50%)
buyback_amount = amount - treasury_amount
```

`EnableBuybackSplit` は、変更不能なトレジャリー受領者が、プール公開と買い戻し経路の凍結のあとに行う不可逆の操作です。これは実在する一度きりの権限です。資金を盗む、停止する、緊急に引き揚げる、アドレスを変えることはできませんが、FeeAccumulator の経済を、トレジャリーのみの立ち上げ蓄積から、トレジャリーと買い戻しの 50/50 分配へ恒久的に変えます。有効化はリリース前チェックを通過してからのみ行われます。

Platho のリリース権限は意図して狭く、ほとんどが一度きりです。それらは確かに存在するので、正直に名指ししておきます。トレジャリーの保有者が ATH の初期供給を一度だけ配備する。ジェネシス制御者が封印前の結び付けと封印を行う。BuybackBurn の起動制御者がプール後の経路を一度だけ凍結する。MarketStabilitySeller の価格凍結はその起動制御者が一度だけ実行する。FeeAccumulator のトレジャリー受領者がリリース前チェック後に不可逆の買い戻し分配を有効化する。いずれの役割も、緊急退避でも、一時停止でも、アップグレードでも、管理者による引き出しでも、残高への恣意的な支配でもありません。

## 買い戻しと焼却

買い戻しは `FeeAccumulator` と `BuybackBurn` を通じて行われます。

BuybackBurn は完全な実行用の封筒のみを受け付けます。

```text
51.05 GRAM
```

封筒の内訳：

```text
50.00 GRAM  - STON.fi のオファー額
1.00 GRAM   - 経路転送のガス
0.05 GRAM   - pTON 送金のガス
```

`50 GRAM` だけでは有効な買い戻しの塊になりません。買い戻しは完全な経路封筒としてのみ受け付けられます。

経路が凍結されたあと、BuybackBurn は次のように買い戻しを実行します。

1. 結び付けられた FeeAccumulator からのみ `51.05 GRAM` を受け取る。
2. その額を `reserve_due_ton` に記録する。
3. `ExecuteBuybackChunk` を受けて封筒を一つ消費する。
4. 凍結された気配値と凍結された minOut を用いる。
5. STON.fi の期限を内部で設定する。
6. 凍結された pTON ウォレット経由で経路を送る。
7. BuybackBurn の公式 ATH ウォレット経由でのみ ATH を受け取る。
8. 送り元ウォレットが凍結された STON.fi プールと一致するか検証する。
9. 受け取った ATH を公式 ATH ウォレット経由で焼却に送る。
10. `ATHMaster` からの `ATHBurnFinalized` を受けて初めて一巡を終える。

買い戻しの成否は、ルーターのメッセージでも、送出した焼却要求でも、ATHWallet の焼却通知でも決まりません。BuybackBurn が ATHMaster から認証済みの `ATHBurnFinalized` を受け取ったときにのみ決まります。その確定が届くまで、BuybackBurn は焼却保留または再試行の状態と見なされます。ダッシュボードやインデクサは、焼却の試行が送られたというだけで ATH を焼却済みと数えてはなりません。

焼却が確定しない場合、受け取った ATH は再試行の未処理分へ移ります。`RetryAthBurnDue` はその未処理分を全額焼却します。

## ネームの費用

`.ath` ネームの登録は、UsernameRegistry の公式 ATH ウォレットを通じて ATH で支払います。

価格：

| ネームの長さ | 価格 |
| ---: | ---: |
| 4 文字 | 10,000 ATH |
| 5 文字 | 1,000 ATH |
| 6 文字以上 | 100 ATH |

UsernameRegistry は正確な価格のみを受け付けます。不足でも超過でもネームは作られません。

受理された鋳造は保留状態を経て `UsernameNFTItem` を配備します。item が確認されるまで、支払いは収益として認識されません。確認後、金額が分けられます。

```text
50% -> treasury_due_ath
50% -> burn_due_ath
```

ネームの鋳造は本人のウォレットの ATH で支払われます。無効なネーム、誤った価格、重複するネームによる拒否は、ATHWallet の通知返金経路を通じて所有者へ返されます。UsernameRegistry はネーム用の外部返金区画を持ちません。

ネームの鋳造による ATH がプロトコルの収益になるのは、対応する item の配備が確認されたあとだけです。

ネームに関する権限は意図的に分けられています。`UsernameRegistry` はネームをただ一つの `UsernameNFTItem` に結び付け、item の状態が現在の所有者を担います。item を移せばネームが移ります。item は標準的な NFT データと、`name = <username>.ath` を含むオンチェーンの TEP-64 メタデータを提供し、メタデータのために Platho のサーバーに依存しません。ネームのバイト列は文字どおりに扱われ、表示のために正規化されません。先頭・末尾・連続・全体が区切り文字であっても、各バイトが許可集合 `a-z`、`0-9`、`_`、`-` に属し、長さが 4..16 であれば有効です。item の配備は試みられたのにその ACK がレジストリへ届かなかった場合、`PrunePendingUsernameMint` は意図的に非破壊です。失敗を推測せず、保留状態を消さず、返金の未処理分も作りません。回復の道は遅れて届く `UsernameItemDeployedAck` か `UsernameNFTItem.ResendDeployedAck` であり、初期化済みの item はなお正統になり得ます。配備が実際に跳ね返った場合、レジストリは公式 ATH ウォレットに保留中の通知を返すよう求めます。ネームと item を結ぶ錨はアドレス導出そのものです。`UsernameRegistry.get_username_item_address(name_hash)` が、そのネームが存在しうる唯一のアドレスを与えます。それ以外のアドレスに配備された `UsernameNFTItem` は正統ではありません。クライアント、インデクサ、画面は、その item だけで `.ath` ネームの所有と扱ってはならず、移転後にレジストリ記録上の所有者を現在の所有者として用いてもなりません。

## アバターの費用

アバター更新の費用：

```text
100 ATH
```

アバターの更新は本人のウォレットの ATH で支払います。本人の ATH ウォレットから ProfileRegistry の公式 ATH ウォレットへの、通知付き送金です。

ProfileRegistry が更新を受け入れるのは、次の条件がすべて満たされたときだけです。

- 金額がちょうど `100 ATH` であること。
- 送信元が ProfileRegistry の公式 ATH ウォレットであること。
- 支払いウォレットが所有者本人の ATH ウォレットであること。
- 所有者ウォレットがベースチェーンにあること。
- アバターのハッシュがゼロでないこと。
- ストリーム識別子がゼロでないこと。
- パート数が 1 から 16 の範囲にあること。
- メディア形式が WebP であること。

受理された更新は新しいアバターの版を作り、費用を分けます。

```text
50 ATH -> treasury_due_ath
50 ATH -> burn_due_ath
```

拒否されたアバター通知は ATHWallet の通知返金経路で返されます。ProfileRegistry は不正な形式の更新のために別の返金区画を作りません。

ProfileRegistry は価格を定めて支払いを清算しますが、プロフィールの状態は一切持ちません。アバターへの認証済みポインタは所有者本人の KeyShard にあります。画像のバイト列は PublicShard の AVATAR 領域にあり、クライアントはそこから、あるいはローカルのキャッシュから WebP を組み立て、保存された `avatar_hash` と突き合わせます。履歴が欠けていたり切り詰められていたりする場合は、利用不可として表示されます。

## Market Stability Seller

MarketStabilitySeller は、公式プールの公開後に ATH を配る公開のコントラクト準備です。

```text
60,000,000 ATH
```

その目的は、薄い流動性が引き起こす初期市場の歪みを減らすことです。ローンチ時、小さなプールは少数の早期購入者によって大きく動かされ得ます。そうなると、Platho で実際の操作をするために ATH が要る人が、人工的な価格の跳ね上がりで買わされかねません。

MarketStabilitySeller は、ローンチ価格の上に透明な供給の階段をつくります。ATH は固定量の階層で売られます。次の階層は前の階層より高く、各階層には量の上限が定められています。証拠に紐づく一度きりの価格凍結のあと、階層の予定は決定的で、チームが手で変えることはできません。

早期の投機家が大量の ATH を吸い上げようとしても、薄いプールから安い流動性を残らず抜き取って転売するのではなく、上がっていく階層価格で公開の準備から買うことになります。Platho のために ATH が要る人は、既知の公開された階層価格で買えます。小さなプールを一度の需要の波で垂直に押し上げる必要はありません。

この準備は市場にトークンを投げ売りしません。自分から売ることはなく、需要のないところに売り圧力を作りません。売却は、誰かが現在の階層から自発的に買ったときにだけ起こります。需要がなければ、準備は静かなままです。

ATH のオンチェーンでの用途は具体的です。

- `.ath` ネームの登録は UsernameRegistry を通じて ATH で支払う。
- アバターのポインタ更新は ProfileRegistry を通じて ATH で支払う。
- 本人のウォレットにある ATH は、活動配布のゲートが開いたあと、公開のプロトコル手数料を下げる。
- 受理されたネームとアバターの費用が、トレジャリーの未処理分と焼却の未処理分を生む。
- BuybackBurn が GRAM のプロトコル手数料で ATH を買い、受け取った ATH を ATHMaster 経由で焼却する。

公開はウォレットから直接 GRAM で支払われます。ATH が公開のトランザクション全体を支払うわけではありません。割引のゲートが開いたあと、プロトコル手数料の部分を下げます。

これにより ATH の需要は具体的なプロトコル操作に結び付きます。`.ath` ネーム、アバターの更新、エアドロップ後の手数料割引、そして買い戻しと焼却の圧力です。MarketStabilitySeller は次の階層が取られる分だけ供給を広げるので、初期のアクセスは薄いプールに左右されず、公開的で決定的です。

準備が売られるのは、プール後の価格凍結を経てからです。

価格凍結は実在する一度きりの起動権限です。プール公開の証拠から階層の基準価格を一度だけ定め、そのあと起動制御者のハッシュは消されます。それ以降 MarketStabilitySeller は、資金を盗む、売却を止める、緊急に残高を抜く、購入者を差し置く、価格表を変えるといったことはできません。

MarketStabilitySeller は最終ジェネシスで `60,000,000 ATH` の準備全額をもって資本化されます。資金は認証された準備供給の流れを通じて公式売り手 ATH ウォレットへ入り、上限は `60,000,000 ATH` です。`mainnet:genesis:verify` は本番リリース前に、売り手が準備全額を担っていること、そして公式売り手 ATH ウォレットの裏付けが `60,000,000 ATH` 以上であることを確認します。公式売り手 ATH ウォレットへの、求めていない通常の ATH 送金は、計上される準備を増やさず、売却可能な供給も広げず、そのまま滞留し得ます。`60,000,000 ATH` を超える残高は追加の準備ではなく警告として扱われます。

売却はプール後の独立した段階です。プール公開の前に準備は売られません。公開時に、証拠に紐づく一度きりの価格凍結が階層の基準価格を定め、以後、階層の予定は決定的で、チームが手で変えることはできません。

準備は 20 の階層に分けられます。

```text
20 * 3,000,000 ATH = 60,000,000 ATH
```

各階層には倍率があります。

```text
x2, x3, x4, ..., x21
```

これがなだらかな価格の階段をつくります。プロジェクトの人気が高まるにつれて市場は追加の ATH 供給を受け取りますが、次の階層は前の階層より高くなります。初期の需要が薄いプールを一挙に突き崩すこともなく、価格の上昇が、ユーティリティトークンを使いづらくする垂直の壁になることもありません。

購入の式：

```text
price = ceil(base_tranche_price * current_multiplier * amount / 3,000,000 ATH)
```

`base_tranche_price` はプール公開後に凍結され、x1 の価格証拠と厳密に一致します。

ローンチ価格 `1 ATH = 0.001 GRAM` では、一階層の x1 価格は次のとおりです。

```text
3,000,000 ATH * 0.001 GRAM = 3,000 GRAM
```

したがって：

| 階層 | 倍率 | 3M ATH あたり | 1 ATH あたり |
| ---: | ---: | ---: | ---: |
| 1 | x2 | 6,000 GRAM | 0.002 GRAM |
| 2 | x3 | 9,000 GRAM | 0.003 GRAM |
| 3 | x4 | 12,000 GRAM | 0.004 GRAM |
| ... | ... | ... | ... |
| 15 | x16 | 48,000 GRAM | 0.016 GRAM |
| ... | ... | ... | ... |
| 20 | x21 | 63,000 GRAM | 0.021 GRAM |

一回の購入で階層の境界を越えることはできません。前の階層の価格で次の階層の ATH を買うことを防ぐためです。

GRAM の収益は、ATH が購入者へ届いたあとにのみ認識されます。ATH の送金が失敗または跳ね返った場合、準備は元に戻され、購入者は支払った GRAM の元本を取り戻し、トレジャリーの未処理分は増えません。

最終階層 x21 が売り切れたあと、MarketStabilitySeller は ATH の価格を調整しなくなります。以後の価格は市場が完全に決めます。流動性、利用可能な供給、`.ath` ネームの需要、アバターの更新、エアドロップ後の手数料割引、そして買い戻しと焼却の圧力です。

x21 の段でも、参照評価額は用途のモデルに比べて控えめなままです。

```text
1 ATH = 0.021 GRAM
100,000,000 ATH = 2,100,000 GRAM
```

x21 の段で、MarketStabilitySeller は計画された準備の放出を終えます。その後の ATH の価格は、流動性、利用の需要、利用可能な供給、買い戻しと焼却の圧力を通じて、完全に市場が決めます。残るプロトコルの配布は、年 `100,000 ATH` を上限とする緩やかな長期権利確定だけです。

## トレジャリーと焼却の区画

UsernameRegistry と ProfileRegistry は、同じ ATH 手数料の分配モデルを用います。

```text
accepted ATH fee -> 50% treasury_due_ath + 50% burn_due_ath
```

トレジャリーの未処理分の掃き出しは、公式 ATH ウォレット経由でトレジャリー受領者へ ATH を送ります。

焼却の未処理分の掃き出しは、公式 ATH ウォレット経由で ATH の焼却要求を送ります。供給が減るのは、ATHMaster で焼却が確定したあとだけです。

失敗経路と跳ね返り経路は、未処理分の区画を元に戻します。記帳は、下流の送金または焼却が完了するまで保たれます。

## ATHWallet の記帳

ATH の残高は決定的な ATHWallet コントラクトに置かれます。

ATHWallet が扱うのは次のとおりです。

- ジェネシス供給の入金。
- 通常の送金。
- 通知付きの送金。
- ネーム鋳造の通知。
- アバターの通知。
- 焼却の要求。
- 通知の確認応答。
- 古くなった通知の刈り取り。
- 跳ね返りや失敗のあとの復旧。

ATH を支払いとして受け取るコントラクトは、任意のアドレスからの直接メッセージを受け付けません。受け付けるのは自身の公式 ATHWallet からの通知だけです。送り元ウォレットの認証は、決定的なウォレット導出を通じて ATHWallet の内部で行われます。

ATH は汎用の jetton ツール向けに TEP-74 に似た送金の入口を備えていますが、Platho のプロトコル操作は認証済みの ATH 通知メッセージを用います。外部の連携は、Platho の通知の流れが汎用の `JettonTransferNotification` を発すると想定してはなりません。

ATHWallet からの送出内部送金は、送り元側の保留記帳と送り元側の確認応答によって守られます。保留中の操作の証拠がないかぎり、跳ね返りの本文から残高が復元されることはありません。

## ATH のライフサイクル

1. `ATHMaster` が `100,000,000 ATH` の固定供給を作る。
2. 一度きりのトレジャリー配備が、供給をトレジャリーの ATH ウォレットに受け取る。
3. 供給が活動、流動性、長期権利確定、市場安定化に配分される。
4. 利用者が自分のウォレットから直接支払ってメッセージを公開する。
5. 公開の成功が `10 ATH` の活動報酬を計上する。
6. `15,000,000 ATH` の活動エアドロップがすべて配り終わり `airdrop_remaining_ath == 0` になると、ATH のプロトコル手数料割引が解錠される。
7. ATH/GRAM プールが参照価格 `1 ATH = 0.001 GRAM` で公開される。
8. プール後の経路証拠と価格証拠が凍結される。
9. MarketStabilitySeller が x2..x21 の階層で準備を売る。
10. 分配が有効になったあと、FeeAccumulator が GRAM のプロトコル手数料をトレジャリーと買い戻しに分ける。
11. BuybackBurn が GRAM の手数料で ATH を買い、ATHMaster 経由で焼却する。
12. ネームとプロフィールの費用が、ATH のトレジャリー未処理分と焼却未処理分を生む。
13. 総供給量が認証済みの焼却によって少しずつ減る。

## 最終的なモデル

ATH は Platho の四つの層を結び付けます。

1. **アプリの利用** — メッセージが活動報酬を生む。
2. **有料の機能** — ネームとアバターに ATH が要る。
3. **割引** — 配布ゲートのあと、ATH の残高がプロトコル手数料を下げる。
4. **供給の縮小** — ATH 手数料の一部と買い戻しの成果が ATHMaster 経由で焼却される。

このモデルは、固定供給と `100,000 GRAM` の参照評価額から始まります。利用者への一次配布は、実際の有料の利用に結び付いています。メッセージは `0.0191 GRAM` から——現在はプライベートメッセージが `0.0191 GRAM`、公開投稿が `0.0203 GRAM`——に加えて、確定したカプセルごとに `10 ATH` の活動ボーナスがつきます。公開・プライベートを問わず、大きなサイズ階級ほど高くなります。このボーナスは返金でも、補償でも、利益の約束でもありません。供給の最初の 15% が配り終わると、プールが公開され、手数料の割引が解錠され、買い戻しの道が開きます。

ATH は Platho の内側で働くトークンとして存在します。活動によって配られ、有料の操作で使われ、プロトコル手数料を下げ、定められた階段に沿って準備から売られ、オンチェーンで焼却されます。市場安定化の階段を過ぎたあと、ATH の将来の価格は市場とプロトコルの利用が決めます。

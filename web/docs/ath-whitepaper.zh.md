# ATH 白皮书

## Platho 协议代币

ATH 是 Platho 的实用型代币。它用于活动奖励、空投后的协议费用折扣、`.ath` 用户名、个人资料头像更新、市场稳定销售、回购与销毁。

ATH 不是管理型代币。它不赋予重写余额、暂停运营、增发供应量或更改用户所有权规则的能力。它的作用是驱动应用经济，并将 Platho 的使用与链上记账连接起来。

本文档描述 Platho 中的 ATH 模型。

## 核心参数

ATH 拥有固定的总供应量：

```text
100,000,000 ATH
```

发行参考价格为：

```text
1 ATH = 0.001 GRAM
```

发行时的完全稀释估值为：

```text
100,000,000 ATH * 0.001 GRAM = 100,000 GRAM
```

ATH 从 `100,000 GRAM` 的参考市值起步。

## 固定供应量

ATH 由 `ATHMaster` 发行。在初始化时，`ATHMaster` 将固定总供应量设置为 `100,000,000 ATH`。

创世之后不存在增发函数。`ATHMaster` 不实现管理员增发、暂停、黑名单、转账税、强制转账或救援式抽取。

初始供应量部署通过 `DeployTreasurySupply` 一次性完成。它将全部供应量发送到国库 ATH 钱包。创世供应量部署无法重复执行。

总供应量只会通过销毁减少。`ATHMaster` 只有在收到来自所有者地址的确定性 ATH 钱包发来的、经过认证的销毁通知后，才会接受销毁。经过验证后，`ATHMaster` 减少 `total_supply` 并发送 `ATHBurnFinalized`。

ATH 销毁是对总供应量的真实削减，而不是转账到某个闲置地址。

## 供应量分配

ATH 供应量在四个类别之间分配：

| 类别 | 占比 | 数量 |
| --- | ---: | ---: |
| 活动空投 | 15% | 15,000,000 ATH |
| 初始流动性 | 15% | 15,000,000 ATH |
| 长期协议归属 | 10% | 10,000,000 ATH |
| 市场稳定储备 | 60% | 60,000,000 ATH |

该分配定义了 Platho 的经济结构：

- 15% 的供应量在资金池启动前通过应用活动分发给用户。
- 15% 的供应量用于初始流动性。
- 10% 的供应量锁定在不可变的长期归属中。
- 60% 的供应量注入 MarketStabilitySeller 并在创世时锁定，然后在资金池后的定价冻结之后，以高于发行价格的档次分批出售。

活动空投与长期归属储备在最终创世时由 Vault 和 ATHVesting 的官方 ATH 钱包背书，发布验证器会在生产发布之前检查这些余额。`60,000,000 ATH` 的市场稳定储备在最终创世时注入 MarketStabilitySeller 并锁定，由其官方卖方 ATH 钱包背书，发布验证器会在生产发布之前检查该背书。储备从一开始就已资本化，但在资金池启动之后、当一次性的证据绑定定价冻结设定基准档次价格之前，它不会被出售。

## 长期协议归属

长期归属储备为：

```text
10,000,000 ATH
```

它由 `ATHVesting` 持有，而不是由某个可变的国库桶持有。归属时间表在合约中固定：

```text
100,000 ATH per 365-day period
100 periods
10,000,000 ATH total
```

任何人都可以在 ATH 归属后触发领取，但受益人是不可变的。合约没有加速、变更受益人、暂停、管理员清扫、救援式抽取或自由裁量释放功能。

在最终创世时，官方 `ATHWallet(owner = ATHVesting, master = ATHMaster)` 必须精确包含 `10,000,000 ATH`。验证器还要求已领取 ATH 为零、处于闲置阶段，且启动前没有待处理的转账。

该储备刻意设计得很缓慢。它为协议开发创造了一个长期视野，而不会在发行时把一个流动的 10M ATH 桶置于市场之上。

## 活动空投

活动空投为：

```text
15,000,000 ATH
```

每次成功发布的奖励：

```text
10 ATH
```

奖励在成功发布后计入用户在 Vault 中的内部 ATH 余额。成功发布意味着 Vault 将载荷发送到 CapsuleHub，CapsuleHub 接受了该条目，并且 Vault 收到了确认。

失败的发布尝试不会产生活动奖励。

奖励记账：

```text
user.ath_balance += 10 ATH
airdrop_remaining -= 10 ATH
```

如果剩余的空投桶低于 10 ATH，则计入剩余金额。一旦该桶耗尽，新的活动奖励便停止。

活动空投在 Vault 中记账，并由预先注资的官方 Vault ATH 钱包背书。

Vault ATH 存入仅支持通过用户 ATHWallet 的带通知转账流程
（`ATHTransferRequestWithNotify`）进入 Vault。手动向官方 Vault ATHWallet 进行的普通 ATH 转账
不受支持：它可以增加官方钱包的原始余额，但不会产生 `Vault.user.ath_balance`，因此
不得被 PWA 显示为一条存入路径。

Vault ATH 提取是经过签名的 Vault 外部命令。下游的 ATHWallet 部署、转账、存储和
ACK 执行储备由用户在 Vault 中的内部 GRAM 余额支付。Vault 只会返还它收到的、经过认证的
ACK/失败/退回价值，减去本地退款储备并以保留的内部价值为上限。

## 活动价格

消息从当前的公开基础价格起步：

```text
from 0.0337 GRAM
```

在 ATH 折扣之前，当前的精确规范示例为：

```text
public post: 0.0337 GRAM
hybrid private 1 KiB capsule: 0.0347 GRAM
```

对于一次成功的发布，用户获得：

```text
10 ATH
```

按发行参考价格计算：

```text
10 ATH * 0.001 GRAM = 0.01 GRAM
```

这将早期 ATH 分发与真实的应用使用绑定在一起。奖励是一种活动奖金，而不是退款、返现、
回扣，也不是 ATH 将补偿一次发布 GRAM 成本的承诺。`10 ATH` 的发行参考价值可能
低于胶囊的 GRAM 成本，而这是有意为之的：用户因真实使用而获得早期的网络所有权，
而不是获得保证的报销。

胶囊定价：1 KiB 公开帖子从 `0.0337 GRAM` 起，混合私密 1 KiB 胶囊从 `0.0347 GRAM` 起。更大的公开或私密胶囊块成本更高，因为所选的 1、2、4、8、16 或 32 KiB
正文会改变 Vault/CapsuleHub 的执行和存储储备。无论胶囊大小如何，每个成功最终确定的
胶囊的奖励始终为 `10 ATH`。

私密发布默认使用混合安全配置：X25519 + ML-KEM-768 + AES-GCM。不存在更便宜的经典私密消息模式。

在官方资金池存在之后，ATH 的交易价格可能高于或低于发行参考价格。活动奖励不是投资回报、盈利预期或价格保证。

## 协议费用与用户价格

在 Vault 内部，协议费用与面向用户的完整成本是分开的。

协议费用：

| 发布类型 | 协议费用 |
| --- | ---: |
| 公开帖子 | 0.010 GRAM |
| 混合私密消息 | 0.010 GRAM |

面向用户的价格包括协议费用、紧凑索引/头部存储捐赠、Vault 本地执行储备以及预期的 ACK 退款：

| 发布类型 | 面向用户的价格 |
| --- | ---: |
| 公开（起） | from 0.0337 GRAM |
| 当前公开帖子的精确示例 | 0.0337 GRAM |
| 当前混合私密 1 KiB 的精确示例 | 0.0347 GRAM |

如果 PWA 收到更高的保守网络估算，它会将估算的超额部分加到规范的最大收费上，向上取整到整洁的 `0.001 GRAM` 步长。ATH 折扣适用于协议费用，而不适用于网络成本或存储储备。此附加费是一个经过签名的安全边际：如果 CapsuleHub 接受了发布，成功的 ACK 仅返还固定的发布 ACK 储备 `30,000,000` nanotons（`0.030 GRAM`）。在 Vault 处理该 ACK 之后，用户在 Vault 内部 GRAM 余额中大约获得 `25,800,000` nanotons 的贷记。超过规范所需价值的部分作为网络/存储储备超额留在 CapsuleHub 中。它不会返还给 Vault，在发布时也不计为 `accrued_plato_fee_ton`。只有超过 CapsuleHub 受保护储备的原始盈余，之后才可以被无需许可地清扫到 FeeAccumulator，在那里它遵循正常的国库/回购记账。CapsuleHub 存储紧凑的、经过认证的条目元数据和正文哈希；沉重的正文从被接受的发布交易历史中恢复并在本地验证。

## ATH 折扣

在活动空投完全分发之后，ATH 会降低消息的协议费用。

折扣仅在剩余活动空投满足以下条件时解锁：

```text
airdrop_remaining_ath == 0 ATH
```

在此之前，协议费用需全额支付。

全额折扣阈值：

```text
10,000 ATH
```

如果用户在 Vault 中的内部 ATH 余额至少为 `10,000 ATH`，则用户就 Platho 费用部分达到全额协议费用折扣档位。网络成本和存储储备仍需支付。

如果余额低于 `10,000 ATH`，费用会线性递减：

```text
raw_discounted_fee = ceil(full_fee * (10,000 ATH - min(user_ath_balance, 10,000 ATH)) / 10,000 ATH)
discounted_fee = raw_discounted_fee
```

计算采用向上取整。按当前常数，公开和私密胶囊的全额协议费用均为 `0.010 GRAM`（`10,000,000 nanotons`），每个胶囊的最大减免为 `0.010 GRAM`。

## 资金池启动

在完整的 `15,000,000 ATH` 活动空投分发完毕之后，ATH/GRAM 资金池启动。

启动顺序为：

1. 用户通过真实的 Platho 使用获得 ATH。
2. 完整的活动空投被分发。
3. ATH 折扣解锁。
4. ATH/GRAM 资金池启动。
5. 资金池后的路由证据和定价证据被冻结。
6. 回购拆分被启用。

资金池从参考价格起步：

```text
1 ATH = 0.001 GRAM
```

初始流动性分配：

```text
15,000,000 ATH
```

按发行价格计算的 GRAM 一侧：

```text
15,000,000 ATH * 0.001 GRAM = 15,000 GRAM
```

在资金池启动前收取的协议费用为初始流动性的整个 GRAM 一侧注资。这是
启动引导的一部分，并不会将活动奖励变成以 GRAM 计价的债权。

资金池围绕一个已经通过应用使用分发出去的代币启动。这将 ATH 与一个没有用户基础的空白挂牌区分开来。

## FeeAccumulator

GRAM 协议费用收集在 `FeeAccumulator` 中。

在回购拆分启用之前，所有累积的 GRAM 都进入国库桶：

```text
accumulated_ton -> treasury_due_ton
```

在拆分启用之前，`buyback_due_ton` 不会增长。

在 `EnableBuybackSplit` 之后，累积的 GRAM 被拆分：

```text
50% -> treasury_due_ton
50% -> buyback_due_ton
```

如果金额以 nanotons 计为奇数，则余数留在回购一侧：

```text
treasury_amount = floor(amount * 50%)
buyback_amount = amount - treasury_amount
```

`EnableBuybackSplit` 是一个单向操作，由不可变的国库接收方在资金池启动和回购路由
冻结之后执行。这是一个真实的一次性权限：它无法窃取资金、暂停、救援或更改地址，但它永久
将 FeeAccumulator 的经济模型从引导期的仅国库累积变为 50/50 的国库/回购拆分。它仅在
发布预检通过之后启用。

Platho 的发布权限刻意设计得很狭窄，且大多是一次性的。它们确实存在，必须诚实地命名：
国库所有者一次性部署初始 ATH 供应量；创世控制器执行预封装绑定和封装；
BuybackBurn 启动控制器一次性冻结资金池后路由；MarketStabilitySeller 的定价冻结由其启动控制器
一次性执行；FeeAccumulator 国库接收方在预检之后启用单向回购拆分。这些
角色中没有一个是救援、暂停、升级、管理员抽取或任意余额控制机制。

## 回购与销毁

回购通过 `FeeAccumulator` 和 `BuybackBurn` 执行。

BuybackBurn 只接受完整的执行信封：

```text
51.05 GRAM
```

信封结构：

```text
50.00 GRAM  - STON.fi offer amount
1.00 GRAM   - route forward gas
0.05 GRAM   - pTON transfer gas
```

原始的 `50 GRAM` 不是一个有效的回购块。回购只能作为完整的路由信封被接受。

在路由冻结之后，BuybackBurn 按如下方式执行回购：

1. 只接受来自绑定的 FeeAccumulator 的 `51.05 GRAM`。
2. 将金额记录在 `reserve_due_ton` 中。
3. 在 `ExecuteBuybackChunk` 时，消耗一个信封。
4. 使用冻结的报价和冻结的 minOut。
5. 在内部设置 STON.fi 的截止时间。
6. 通过冻结的 pTON 钱包发送路由。
7. 只通过官方 BuybackBurn ATH 钱包接受 ATH。
8. 验证源钱包与冻结的 STON.fi 资金池匹配。
9. 通过官方 ATH 钱包将收到的 ATH 发送去销毁。
10. 仅在收到来自 `ATHMaster` 的 `ATHBurnFinalized` 之后完成本轮循环。

回购成功不是由路由器消息、出站销毁请求或 ATHWallet 销毁通知来定义的。它仅
在 BuybackBurn 收到来自 ATHMaster 的、经过认证的 `ATHBurnFinalized` 时才被定义。在该最终确认到达之前，
BuybackBurn 仍必须被视为待销毁或重试状态；仪表盘和索引器不得仅仅因为发送了一次销毁尝试
就将该 ATH 计为已销毁。

如果销毁未能最终确定，收到的 ATH 进入重试待处理。`RetryAthBurnDue` 销毁全部重试待处理金额。

## 用户名费用

`.ath` 用户名注册通过官方 UsernameRegistry ATH 钱包以 ATH 支付。

价格：

| 名称长度 | 价格 |
| ---: | ---: |
| 4 个字符 | 10,000 ATH |
| 5 个字符 | 1,000 ATH |
| 6 个及以上字符 | 100 ATH |

UsernameRegistry 只接受精确的价格。少付和多付都不会产生一个名称。

一次被接受的铸造会经过待处理状态并部署 `UsernameNFTItem`。在条目确认之前，付款不被确认为收入。在条目确认之后，金额被拆分：

```text
50% -> treasury_due_ath
50% -> burn_due_ath
```

用户名铸造由 Vault 出资。无效用户名、错误价格或重名被拒绝时，会通过
官方 ATH 钱包通知路径退回，以便 Vault 恢复用户的内部 ATH。在当前的 Vault 出资流程中，UsernameRegistry 不维护一个
直接的外部用户名退款桶。

来自用户名铸造的 ATH 只有在对应条目的部署被确认之后，才成为协议收入。

用户名权限被刻意拆分：`UsernameRegistry` 将名称锚定到唯一确切的 `UsernameNFTItem`，而
条目状态承载当前所有者。条目的转移就转移了用户名。该条目暴露标准的 NFT 数据
和 TEP-64 链上元数据，包括 `name = <username>.ath`；它不依赖 Platho 服务器来提供元数据。
用户名字节是字面的，且不做显示规范化：只要每个字节都在允许的 `a-z`、`0-9`、`_`、`-` 集合内且长度为 4..16，
开头、结尾、连续以及全为分隔符的名称都是有效的。
如果条目部署已尝试但条目 ACK 从未到达注册表，`PrunePendingUsernameMint` 刻意设计为
非破坏性：它不会猜测失败、删除待处理状态或产生退款待处理。恢复路径是一条迟到的
`UsernameItemDeployedAck` 或 `UsernameNFTItem.ResendDeployedAck`，因此一个已初始化的条目仍能成为权威。
如果条目部署实际发生退回，注册表会请求官方 ATH 钱包退还该待处理通知。
一个已部署的 `UsernameNFTItem`，如果 `UsernameRegistry.name_records[name_hash]` 未指向那个确切的条目，则是
非权威的：客户端、索引器和 UI 不得仅凭该条目本身就将其视为对 `.ath` 名称的所有权，并且在转移之后不得
将注册表记录的所有者当作当前所有者。

## 个人资料头像费用

个人资料头像更新费用：

```text
100 ATH
```

个人资料头像更新由 Vault 出资。PWA 向 Vault 发送 `SetProfileAvatarFromVaultBalance`；Vault 通过其官方 ATH 钱包通知路径支付到官方 ProfileRegistry ATH 钱包。不支持直接的用户钱包头像付款。

只有在满足所有条件时，ProfileRegistry 才接受更新：

- 金额恰好为 `100 ATH`；
- 发送方是官方 ProfileRegistry ATH 钱包；
- 付款人钱包是绑定的 Vault；
- 所有者钱包位于 basechain；
- 头像哈希不为零；
- stream id 不为零；
- 分片数量在 1 到 16 之间；
- 媒体格式为 WebP。

一次被接受的更新会创建一个新的头像版本并拆分费用：

```text
50 ATH -> treasury_due_ath
50 ATH -> burn_due_ath
```

被拒绝的头像通知会通过 ATHWallet 通知退回路径退款。ProfileRegistry 不会为格式错误的头像更新创建单独的退款桶。

ProfileRegistry 存储经过认证的头像指针，而不是永久的图像字节。PWA 必须从公开的 CapsuleHub 条目或本地缓存重建头像 WebP 数据，并根据存储的 `avatar_hash` 验证字节；缺失或被剪枝的历史会显示为不可用。

## 市场稳定卖方

MarketStabilitySeller 是一个在官方资金池启动后分发 ATH 的公共合约储备：

```text
60,000,000 ATH
```

它的目的是减少由稀薄流动性造成的早期市场扭曲。在启动时，一个小型资金池可能被一小群早期买家剧烈推动。如果发生这种情况，需要 ATH 来进行实际 Platho 操作的用户可能被迫在人为的价格飙升中买入。

MarketStabilitySeller 在发行价格之上创建一个透明的供应阶梯。它以固定大小的档次出售 ATH。下一个档次都比前一个更贵，且每个档次都有一个硬性大小上限。在一次性的证据绑定定价冻结之后，档次时间表是确定性的，团队无法手动更改。

如果早期投机者试图吸收大量 ATH，他们会以递增的档次价格从公共储备中购买，而不是从稀薄的资金池中抽干所有廉价流动性再转售给用户。如果普通用户需要 ATH 来使用 Platho，他们可以按已知的公共档次价格购买，而无需用单一的需求浪潮把一个小型资金池垂直推高。

该储备不会向市场倾销代币。它不会自行出售，也不会在没有需求的情况下制造抛压。只有当买家自愿从当前档次购买时，销售才会发生。如果没有需求，储备保持闲置。

ATH 的链上实用性是具体的：

- `.ath` 用户名注册通过 UsernameRegistry 以 ATH 支付；
- 个人资料头像指针更新通过 ProfileRegistry 以 ATH 支付；
- 在活动分发门槛之后，用户内部 Vault 余额中持有的 ATH 会降低 Vault 发布的协议费用；
- 被接受的用户名和头像费用产生国库待处理和销毁待处理；
- BuybackBurn 用协议 GRAM 费用购买 ATH，并通过 ATHMaster 销毁收到的 ATH。

Vault 发布以 GRAM 支付。ATH 不支付整笔发布交易。它在折扣门槛开启之后降低协议费用部分。

这使得 ATH 的需求与具体的协议操作绑定：`.ath` 名称、头像更新、空投后的 Vault 协议费用折扣以及回购/销毁压力。MarketStabilitySeller 只在买家取走下一个档次时才扩大可用供应量，因此早期获取是公开且确定性的，而不是被一个稀薄的资金池所主导。

该储备仅在资金池后的定价冻结之后出售。

定价冻结是一个真实的一次性启动权限。它根据资金池启动证据一次性设定基准档次价格，随后启动控制器哈希被清除。此后，MarketStabilitySeller 无法窃取资金、暂停销售、救援余额、覆盖买家或篡改价格时间表。

MarketStabilitySeller 在最终创世时以完整的 `60,000,000 ATH` 储备资本化，通过
经过认证的储备注资流程注入官方卖方 ATH 钱包，直至 `60,000,000 ATH` 的硬性上限。
`mainnet:genesis:verify` 会在生产发布之前检查卖方承载完整储备，且其官方卖方 ATH 钱包背书
至少为 `60,000,000 ATH`。一笔未经请求的、进入官方卖方 ATH
钱包的普通 ATH 转账不会增加已记账的储备，不会扩大可售供应量，并且可能保持卡住；钱包余额
超过 `60,000,000 ATH` 会被视为一个警告，而非额外储备。

出售是一个独立的资金池后步骤。储备在资金池启动之后、当一次性的证据绑定
定价冻结设定基准档次价格之前不会被出售；此后档次时间表是确定性的，团队无法手动
更改。

储备被拆分为 20 个档次：

```text
20 * 3,000,000 ATH = 60,000,000 ATH
```

每个档次都有一个乘数：

```text
x2, x3, x4, ..., x21
```

这创造了一个平滑的价格阶梯。随着项目人气增长，市场获得额外的 ATH 供应量，但下一个档次都比前一个更贵。早期需求不会立刻冲击稀薄的资金池，价格增长也不会变成一堵让这个实用型代币难以使用的垂直墙。

购买公式：

```text
price = ceil(base_tranche_price * current_multiplier * amount / 3,000,000 ATH)
```

`base_tranche_price` 在资金池启动后被冻结，并与 x1 定价证据完全匹配。

在发行价格 `1 ATH = 0.001 GRAM` 下，一个档次的 x1 价格为：

```text
3,000,000 ATH * 0.001 GRAM = 3,000 GRAM
```

因此：

| 档次 | 乘数 | 3M ATH 的价格 | 每 1 ATH 的价格 |
| ---: | ---: | ---: | ---: |
| 1 | x2 | 6,000 GRAM | 0.002 GRAM |
| 2 | x3 | 9,000 GRAM | 0.003 GRAM |
| 3 | x4 | 12,000 GRAM | 0.004 GRAM |
| ... | ... | ... | ... |
| 15 | x16 | 48,000 GRAM | 0.016 GRAM |
| ... | ... | ... | ... |
| 20 | x21 | 63,000 GRAM | 0.021 GRAM |

单次购买不能跨越档次边界。这防止以前一个档次的价格从下一个档次购买 ATH。

GRAM 收入只有在 ATH 交付给买家之后才被确认。如果 ATH 转账失败或退回，储备会被恢复，买家会收回已支付的 GRAM 本金，且国库待处理不会增加。

在最终的 x21 档次售出之后，MarketStabilitySeller 不再调节 ATH 价格。从那时起，价格完全由市场决定：流动性、可用供应量、对 `.ath` 名称的需求、头像更新、空投后的 Vault 协议费用折扣以及回购/销毁压力。

即使在 x21 档次，相对于实用模型，参考估值仍保持适度：

```text
1 ATH = 0.021 GRAM
100,000,000 ATH = 2,100,000 GRAM
```

在 x21 档次，MarketStabilitySeller 已完成其程序化的储备释放。此后，ATH 价格完全由流动性、使用需求、可用供应量以及回购/销毁压力等市场因素决定。唯一剩下的协议分配是缓慢的长期归属时间表，上限为每年 `100,000 ATH`。

## 国库与销毁桶

UsernameRegistry 和 ProfileRegistry 使用相同的 ATH 费用拆分模型：

```text
accepted ATH fee -> 50% treasury_due_ath + 50% burn_due_ath
```

国库待处理刷新会通过官方 ATH 钱包将 ATH 发送到国库接收方。

销毁待处理刷新会通过官方 ATH 钱包发送一条 ATH 销毁请求。供应量只有在 ATHMaster 中的销毁最终确定之后才会减少。

失败和退回路径会恢复待处理桶。在下游转账或销毁完成之前，记账会被保留。

## ATHWallet 记账

ATH 余额存在于确定性的 ATHWallet 合约中。

ATHWallet 处理：

- 创世供应量贷记；
- 普通转账；
- 带通知的转账；
- 用户名铸造通知；
- 个人资料头像通知；
- 销毁请求；
- 通知确认；
- 陈旧通知剪枝；
- 退回/失败恢复。

接受 ATH 作为付款的合约不接受来自任意地址的直接消息。它们只接受来自其官方 ATHWallet 的通知。源钱包认证在 ATHWallet 内部通过确定性钱包派生完成。

ATH 为通用 jetton 工具暴露了类 TEP-74 的转账入口，但 Platho 协议操作使用经过认证的 ATH 通知消息。外部集成不得假设 Platho 通知流程会发出通用的 `JettonTransferNotification`。

ATHWallet 中的出站内部转账受源侧待处理记账和源确认保护。没有待处理证明，余额不会从退回体中恢复。

## ATH 生命周期

1. `ATHMaster` 创建 `100,000,000 ATH` 的固定供应量。
2. 一次性的国库部署在国库 ATH 钱包中接收供应量。
3. 供应量在活动、流动性、长期归属和市场稳定之间分配。
4. 用户通过 Vault 发布消息。
5. 一次成功的发布贷记 `10 ATH` 活动奖励。
6. 在完整的 `15,000,000 ATH` 活动空投分发完毕且 `airdrop_remaining_ath == 0` 之后，ATH 协议费用折扣解锁。
7. ATH/GRAM 资金池以参考价格 `1 ATH = 0.001 GRAM` 启动。
8. 资金池后的路由证据和定价证据被冻结。
9. MarketStabilitySeller 通过 x2..x21 档次出售储备。
10. 在拆分启用之后，FeeAccumulator 将协议 GRAM 费用在国库和回购之间划分。
11. BuybackBurn 用 GRAM 协议费用购买 ATH，并通过 ATHMaster 销毁 ATH。
12. 用户名和个人资料费用产生 ATH 国库待处理和 ATH 销毁待处理。
13. 总供应量通过经过认证的销毁逐步减少。

## 最终模型

ATH 连接 Platho 的四个层面：

1. **应用使用** —— 消息产生活动奖励。
2. **付费功能** —— 用户名和头像需要 ATH。
3. **折扣** —— ATH 余额在分发门槛之后降低协议费用。
4. **供应量削减** —— 部分 ATH 费用和回购产出通过 ATHMaster 销毁。

该模型以固定供应量和 `100,000 GRAM` 的参考估值起步。主要的用户分发与真实的付费使用绑定：消息从 `0.0337 GRAM` 起步 —— 目前 1 KiB 公开帖子为 `0.0337 GRAM`，混合私密 1 KiB 胶囊为 `0.0347 GRAM`，外加每个最终确定胶囊 `10 ATH` 的活动奖金。更大的公开或私密尺寸类别成本更高。该奖金不是退款、报销或盈利承诺。在前 15% 的供应量分发之后，资金池启动，协议费用折扣解锁，回购路径开启。

ATH 作为一个可用的代币存在于 Platho 内部：它通过活动分发，用于付费操作，降低协议费用，通过既定的阶梯从储备中出售，并通过链上销毁被销毁。在市场稳定阶梯之后，ATH 未来的价格由市场和协议使用决定。

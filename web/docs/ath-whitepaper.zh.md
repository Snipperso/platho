# ATH 白皮书

## Platho 协议代币

ATH 是 Platho 的实用型代币。它用于活动奖励、空投后的协议费折扣、`.ath` 用户名、资料头像更新、市场稳定性销售、回购与销毁。

ATH 不是管理型代币。它不授予改写余额、暂停运营、增发新供应或更改用户所有权规则的能力。它的作用是驱动应用经济，并将 Platho 的使用与链上会计连接起来。

本文档描述 Platho v1 中的 ATH 模型。

## 核心参数

ATH 拥有固定的总供应量：

```text
100,000,000 ATH
```

ATH 使用 9 位小数：

```text
1 ATH = 1,000,000,000 atomic units
```

以原子单位计的总供应量：

```text
100,000,000,000,000,000
```

发行参考价格为：

```text
1 ATH = 0.001 GRAM
```

发行时的完全稀释估值为：

```text
100,000,000 ATH * 0.001 GRAM = 100,000 GRAM
```

ATH 起始于 `100,000 GRAM` 的参考市值。

## 固定供应量

ATH 由 `ATHMaster` 发行。初始化时，`ATHMaster` 将固定总供应量设定为 `100,000,000 ATH`。

创世之后没有增发功能。`ATHMaster` 不实现管理员铸造、暂停、黑名单、转账税、强制转账或救援式抽取。

初始供应部署通过 `DeployTreasurySupply` 执行一次。它将全部供应发送到国库 ATH 钱包。创世供应部署无法重复执行。

总供应量只能通过销毁减少。`ATHMaster` 只有在收到来自所有者地址的确定性 ATH 钱包发出的、经过认证的销毁通知后，才接受一次销毁。验证之后，`ATHMaster` 减少 `total_supply` 并发送 `ATHBurnFinalized`。

ATH 销毁是对总供应量的真实削减，而非转移到某个未使用地址。

## 供应分配

ATH 供应分配到四个类别：

| 类别 | 份额 | 数量 |
| --- | ---: | ---: |
| 活动空投 | 15% | 15,000,000 ATH |
| 初始流动性 | 15% | 15,000,000 ATH |
| 长期协议归属 | 10% | 10,000,000 ATH |
| 市场稳定储备 | 60% | 60,000,000 ATH |

该分配定义了 Platho 的经济结构：

- 15% 的供应在资金池启动前通过应用活动分发给用户。
- 15% 的供应用于初始流动性。
- 10% 的供应锁定在不可变的长期归属中。
- 60% 的供应为 MarketStabilitySeller 预留，在资金池上线后的定价冻结及储备注资就绪门控通过之后，以高于发行价的价格分批出售。

活动空投与长期归属储备在最终创世时由 Vault 与 ATHVesting 的官方 ATH 钱包背书，发布验证器会在生产发布前检查这些余额。`60,000,000 ATH` 的市场稳定分配为 MarketStabilitySeller 预留，但在最终创世时并不会注资到销售方。销售方注资只发生在资金池启动、一次性的证据绑定定价冻结，以及受绑定的储备注资方通知流程之后；只有在 `reserve_due_ath`、`reserve_funded_total_ath` 以及官方销售方 ATH 钱包背书都经过验证之后，销售方就绪状态才有效。

## 长期协议归属

长期归属储备为：

```text
10,000,000 ATH
```

它由 `ATHVesting` 持有，而不是由某个可变的国库分桶持有。归属计划在合约中固定：

```text
100,000 ATH per 365-day period
100 periods
10,000,000 ATH total
```

一旦 ATH 归属完成，任何人都可以触发领取，但受益人不可变更。合约没有加速、变更受益人、暂停、管理员清扫、救援式抽取或自由裁量释放的功能。

在最终创世时，官方的 `ATHWallet(owner = ATHVesting, master = ATHMaster)` 必须恰好包含 `10,000,000 ATH`。验证器还要求已领取的 ATH 为零、处于闲置阶段，且在启动前没有待处理的转账。

这个储备被有意设计得缓慢。它为协议开发创造了长远的时间跨度，而不会在启动时把一个流动性充足的 10M ATH 分桶置于市场之上。

## 活动空投

活动空投为：

```text
15,000,000 ATH
```

每次成功发布的奖励：

```text
10 ATH
```

在一次成功发布之后，奖励会计入用户在 Vault 中的内部 ATH 余额。一次成功发布意味着 Vault 已将载荷发送给 CapsuleHub，CapsuleHub 接受了该条目，并且 Vault 收到了确认。

失败的发布尝试不会产生活动奖励。

奖励会计：

```text
user.ath_balance += 10 ATH
airdrop_remaining -= 10 ATH
```

如果剩余的空投分桶低于 10 ATH，则计入剩余的数额。一旦分桶耗尽，新的活动奖励便停止。

活动空投在 Vault 中记账，并由预先注资的官方 Vault ATH 钱包背书。

Vault 的 ATH 存入只支持通过用户 ATHWallet 的带通知转账流程
（`ATHTransferRequestWithNotify`）进入 Vault。向官方 Vault ATHWallet 进行手动的普通 ATH 转账
是不受支持的：它可以增加官方钱包的原始余额，但不会创建 `Vault.user.ath_balance`，并且 PWA 一定不能
将其显示为存入路径。

Vault 的 ATH 提取是经过签名的 Vault 外部命令。下游 ATHWallet 的部署、转账、存储和
ACK 执行储备，由用户在 Vault 中的内部 GRAM 余额支付。Vault 只把它收到的、经过认证的
ACK/失败/退回价值回记，扣除本地退款储备，并以预留的内部价值为上限。产品
文案一定不能承诺完整的超额 GRAM 退款。

## 活动价格

公开的产品文案可以表述为消息从当前确切的公开基础价格起：

```text
from 0.0337 GRAM
```

在 ATH 折扣之前，当前确切的标准示例为：

```text
public post: 0.0337 GRAM
hybrid private 1 KiB capsule: 0.0347 GRAM
```

对于一次成功发布，用户获得：

```text
10 ATH
```

按发行参考价格计算：

```text
10 ATH * 0.001 GRAM = 0.01 GRAM
```

这将早期的 ATH 分发与真实的应用使用绑定在一起。该奖励是活动奖金，而不是退款、返现、
回扣，或对 ATH 将补偿一次发布 GRAM 成本的承诺。`10 ATH` 的发行参考价值可能
低于胶囊的 GRAM 成本，而这是有意为之的：用户因真实使用而获得早期网络所有权，
而不是获得保证的报销。

产品文案可以将胶囊定价概括为消息从 `0.0337 GRAM` 起；当前确切的标准示例是 1 KiB 公开帖子从 `0.0337 GRAM` 起，混合私密 1 KiB 胶囊从 `0.0347 GRAM` 起。更大的公开或私密胶囊块成本更高，因为所选的 1、2、4、8、16 或 32 KiB
正文会改变 Vault/CapsuleHub 的执行与存储储备。无论胶囊大小如何，每个成功最终确定的
胶囊的奖励仍为 `10 ATH`。

私密发布默认使用混合安全配置：X25519 + ML-KEM-768 + AES-GCM。V1 中没有更便宜的经典私密消息模式。

在官方资金池存在之后，ATH 可能在发行参考价格之上或之下交易。协议文档一定不能将
活动奖励呈现为投资回报、盈利预期或价格保证。

## 协议费与用户价格

在 Vault 内部，协议费与面向用户的完整成本是分开的。

协议费：

| 发布类型 | 协议费 |
| --- | ---: |
| 公开帖子 | 0.010 GRAM |
| 混合私密消息 | 0.010 GRAM |

面向用户的价格包含协议费、紧凑的索引/头部存储捐赠、Vault 本地执行储备以及预期的 ACK 退款：

| 发布类型 | 面向用户的价格 |
| --- | ---: |
| 公开/产品标签 | from 0.0337 GRAM |
| 当前公开帖子确切示例 | 0.0337 GRAM |
| 当前混合私密 1 KiB 确切示例 | 0.0347 GRAM |

如果 PWA 收到更高的保守网络估算，它会将估算的超出部分加到标准最大收费上，并向上取整到整洁的 `0.001 GRAM` 步进。ATH 折扣适用于协议费，而不适用于网络成本或存储储备。这个附加费是一个经过签名的安全边际：如果 CapsuleHub 接受了发布，成功 ACK 只返回固定的发布 ACK 储备 `30,000,000` nanotons（`0.030 GRAM`）。在 Vault 处理该 ACK 之后，用户在 Vault 内部 GRAM 余额中大约被计入 `25,800,000` nanotons。高于标准所需值的部分作为网络/存储储备超额留在 CapsuleHub 中。它不会返还给 Vault，也不会在发布时计为 `accrued_plato_fee_ton`。只有高于 CapsuleHub 受保护储备的原始盈余，之后才可以被无需许可地清扫到 FeeAccumulator，在那里它遵循正常的国库/回购会计。CapsuleHub 存储紧凑的、经过认证的条目元数据和正文哈希；沉重的正文从已接受的发布交易历史中恢复，并在本地验证。

## ATH 折扣

在活动空投已全部分发之后，ATH 会降低消息协议费。

折扣只有在剩余活动空投满足以下条件时才解锁：

```text
airdrop_remaining_ath == 0 ATH
```

在此之前，协议费需全额支付。

完整折扣阈值：

```text
10,000 ATH
```

如果用户在 Vault 中的内部 ATH 余额至少为 `10,000 ATH`，则用户在 Platho 费用部分达到完整的协议费折扣档位。网络成本和存储储备仍需支付。

如果余额低于 `10,000 ATH`，费用会线性递减：

```text
raw_discounted_fee = ceil(full_fee * (10,000 ATH - min(user_ath_balance, 10,000 ATH)) / 10,000 ATH)
discounted_fee = raw_discounted_fee
```

该计算向上取整。按当前常量，公开和私密胶囊的完整协议费均为 `0.010 GRAM`（`10,000,000 nanotons`），每个胶囊的最大减免为 `0.010 GRAM`。

## 资金池启动

ATH/GRAM 资金池在全部 `15,000,000 ATH` 活动空投分发完毕后启动。

启动顺序为：

1. 用户通过真实的 Platho 使用获得 ATH。
2. 全部活动空投分发完毕。
3. ATH 折扣解锁。
4. ATH/GRAM 资金池启动。
5. 资金池后的路由证据和定价证据被冻结。
6. 回购拆分被启用。

资金池起始于参考价格：

```text
1 ATH = 0.001 GRAM
```

初始流动性分配：

```text
15,000,000 ATH
```

按启动价格计的 GRAM 侧：

```text
15,000,000 ATH * 0.001 GRAM = 15,000 GRAM
```

在资金池启动前收取的协议费预计不足以完全为初始流动性的 GRAM 侧注资。
初始流动性计划可能需要在协议收入之外由项目/国库注资。这是启动
引导的一部分，并不会把活动奖励变成以 GRAM 计价的债权。

资金池围绕一个已经通过应用使用分发的代币启动。这将 ATH 与一个没有用户基础的空壳上市区分开来。

## FeeAccumulator

GRAM 协议费在 `FeeAccumulator` 中收取。

在回购拆分被启用之前，所有累积的 GRAM 都流向国库分桶：

```text
accumulated_ton -> treasury_due_ton
```

在拆分被启用之前，`buyback_due_ton` 不会增长。

在 `EnableBuybackSplit` 之后，累积的 GRAM 被拆分：

```text
50% -> treasury_due_ton
50% -> buyback_due_ton
```

如果以 nanotons 计的金额为奇数，余数留在回购一侧：

```text
treasury_amount = floor(amount * 50%)
buyback_amount = amount - treasury_amount
```

`EnableBuybackSplit` 是一次性的单向操作，由不可变的国库接收方在资金池启动和回购路由
冻结之后执行。这是一项真实的一次性权限：它无法窃取资金、暂停、救援或更改地址，但它永久
将 FeeAccumulator 的经济从引导期的仅国库累积改为 50/50 的国库/回购拆分。它
只有在发布预检通过之后才被启用。

Platho 的发布权限是有意收窄且大多为一次性的。它们确实存在，且必须被诚实地命名：
国库所有者部署初始 ATH 供应一次；创世控制器执行预封存绑定与封存；
BuybackBurn 启动控制器冻结资金池后的路由一次；MarketStabilitySeller 的定价冻结由其启动控制器
执行一次；FeeAccumulator 的国库接收方在预检之后启用单向回购拆分。这些
角色都不是救援、暂停、升级、管理员抽取或任意余额控制机制。

## 回购与销毁

回购通过 `FeeAccumulator` 和 `BuybackBurn` 执行。

BuybackBurn 只接受完整的执行信封：

```text
51.05 GRAM
```

信封结构：

```text
50.00 GRAM  - STON.fi offer amount
1.00 GRAM   - route forward gas
0.05 GRAM   - pTON transfer gas
```

原始的 `50 GRAM` 不是有效的回购块。回购只作为完整的路由信封被接受。

在路由冻结之后，BuybackBurn 按如下方式执行一次回购：

1. 只从受绑定的 FeeAccumulator 接受 `51.05 GRAM`。
2. 将金额记入 `reserve_due_ton`。
3. 在 `ExecuteBuybackChunk` 时，消耗一个信封。
4. 使用冻结的报价和冻结的 minOut。
5. 在内部设置 STON.fi 截止时间。
6. 通过冻结的 pTON 钱包发送路由。
7. 只通过官方 BuybackBurn ATH 钱包接受 ATH。
8. 验证来源钱包与冻结的 STON.fi 资金池匹配。
9. 通过官方 ATH 钱包将收到的 ATH 发送去销毁。
10. 只有在收到来自 `ATHMaster` 的 `ATHBurnFinalized` 之后才完成该周期。

回购的成功不是由路由器消息、出站销毁请求或 ATHWallet 销毁通知定义的。它只有
在 BuybackBurn 收到来自 ATHMaster 的、经过认证的 `ATHBurnFinalized` 时才被定义。在该最终确认到达之前，
BuybackBurn 仍必须被视为待销毁或重试状态；仪表盘和索引器一定不能仅仅因为发送了
一次销毁尝试就把该 ATH 计为已销毁。

如果销毁未最终确认，收到的 ATH 会转入重试待处理。`RetryAthBurnDue` 销毁全部重试待处理金额。

## 用户名费用

`.ath` 用户名注册通过官方 UsernameRegistry ATH 钱包以 ATH 支付。

价格：

| 名称长度 | 价格 |
| ---: | ---: |
| 4 个字符 | 10,000 ATH |
| 5 个字符 | 1,000 ATH |
| 6+ 个字符 | 100 ATH |

UsernameRegistry 只接受确切的价格。支付不足和支付过多都不会创建名称。

一次被接受的铸造会经过待处理状态并部署 `UsernameNFTItem`。在条目确认之前，付款不被认定为收入。在条目确认之后，金额被拆分：

```text
50% -> treasury_due_ath
50% -> burn_due_ath
```

当前 V1 用户名铸造由 Vault 注资。无效用户名、错误价格或重名的拒绝会通过
官方 ATH 钱包通知路径退回，以便 Vault 恢复用户的内部 ATH。在当前由 Vault 注资的流程中，UsernameRegistry 不维护
直接的外部用户名退款分桶。

来自用户名铸造的 ATH 只有在对应条目的部署被确认之后才成为协议收入。

用户名权限被有意拆分：`UsernameRegistry` 将名称锚定到恰好一个 `UsernameNFTItem`，而
条目状态承载当前所有者。条目的转让即转让用户名。条目暴露标准 NFT 数据
和 TEP-64 链上元数据，包括 `name = <username>.ath`；它不依赖 Platho 服务器提供元数据。
V1 用户名字节是字面的，且不做显示归一化：当每个字节都在允许的 `a-z`、`0-9`、`_`、`-` 集合中
且长度为 4..16 时，前导、尾随、连续以及全部为分隔符的名称都是有效的。
如果条目部署已尝试但条目 ACK 从未到达注册表，`PrunePendingUsernameMint` 在 V1 中被有意设计为
非破坏性：它不猜测失败、不删除待处理状态，也不创建退款待处理。恢复路径是一次迟到的
`UsernameItemDeployedAck` 或 `UsernameNFTItem.ResendDeployedAck`，因此一个已初始化的条目仍然可以成为权威。
如果条目部署确实退回，注册表会要求官方 ATH 钱包退还该待处理通知。
一个已部署但没有 `UsernameRegistry.name_records[name_hash]` 指向该确切条目的 `UsernameNFTItem` 是
非权威的：客户端、索引器和 UI 一定不能仅凭该条目就将其视为 `.ath` 名称的所有权，也一定不能
在发生转让之后将注册表记录的所有者用作当前所有者。

## 资料头像费用

资料头像更新成本：

```text
100 ATH
```

当前 V1 资料头像更新由 Vault 注资。PWA 向 Vault 发送 `SetProfileAvatarFromVaultBalance`；Vault 通过其官方 ATH 钱包通知路径向官方 ProfileRegistry ATH 钱包支付。用户钱包直接支付头像费用不是受支持的 V1 产品流程。

ProfileRegistry 只有在满足所有条件时才接受更新：

- 金额恰好为 `100 ATH`；
- 发送方是官方 ProfileRegistry ATH 钱包；
- 付款方钱包是受绑定的 Vault；
- 所有者钱包位于基础链（basechain）；
- 头像哈希不为零；
- 流 id 不为零；
- 分片计数为 1 到 16；
- 媒体格式为 WebP。

一次被接受的更新会创建一个新的头像版本，并拆分费用：

```text
50 ATH -> treasury_due_ath
50 ATH -> burn_due_ath
```

被拒绝的头像通知通过 ATHWallet 通知退回路径退款。ProfileRegistry 不为格式错误的头像更新创建单独的退款分桶。

ProfileRegistry 存储经过认证的头像指针，而不是永久的图像字节。PWA 必须从公开的 CapsuleHub 条目或本地缓存重建头像 WebP 数据，并根据存储的 `avatar_hash` 验证字节；缺失或已被裁剪的历史显示为不可用。

## 市场稳定销售方（Market Stability Seller）

MarketStabilitySeller 是一个公开合约储备，在官方资金池启动后分发 ATH：

```text
60,000,000 ATH
```

它的目的是减少由薄弱流动性造成的早期市场扭曲。在启动时，一个小资金池可能被一小群早期买家剧烈推动。如果发生这种情况，那些出于实际 Platho 操作而需要 ATH 的用户可能被迫在人为的价格飙升中买入。

MarketStabilitySeller 在发行价之上创造一个透明的供应阶梯。它以固定规模的分批出售 ATH。每一个下一批都比前一批更贵，并且每一批都有硬性规模上限。在一次性的证据绑定定价冻结之后，分批计划是确定性的，且不能被团队手动更改。

如果早期投机者试图吸收大量 ATH，他们会以递增的分批价格从公开储备买入，而不是从薄弱的资金池中抽走所有廉价流动性再转卖给用户。如果普通用户为了 Platho 而需要 ATH，他们可以在已知的公开分批价格买入，而不会用单一的需求浪潮把一个小资金池垂直推高。

该储备不会把代币倾倒进市场。它不会自行出售，也不会在没有需求的情况下制造抛售压力。销售只在买家自愿从当前批次购买时才发生。如果没有需求，储备保持闲置。

ATH 的链上实用性是具体的：

- `.ath` 用户名注册通过 UsernameRegistry 以 ATH 支付；
- 资料头像指针更新通过 ProfileRegistry 以 ATH 支付；
- 用户在 Vault 内部余额中持有的 ATH，在活动分发门控之后降低 Vault 发布的协议费；
- 被接受的用户名和头像费用创建国库待处理和销毁待处理；
- BuybackBurn 用协议 GRAM 费用购买 ATH，并通过 ATHMaster 销毁收到的 ATH。

Vault 发布以 GRAM 支付。ATH 不支付整个发布交易。它在折扣门控开启之后降低协议费部分。

这使得 ATH 需求与具体的协议操作绑定：`.ath` 名称、头像更新、空投后的 Vault 协议费折扣，以及回购/销毁压力。MarketStabilitySeller 只在买家取用下一批时才扩大可用供应，因此早期获取是公开且确定性的，而不会被一个薄弱的资金池所主导。

该储备只在资金池后的定价冻结之后出售。

定价冻结是一项真实的一次性启动权限。它根据资金池启动证据一次性设定基础分批价格，然后启动控制器哈希被清除。此后，MarketStabilitySeller 无法窃取资金、暂停销售、救援余额、覆盖买家或篡改价格计划。

MarketStabilitySeller 的就绪状态是一个资金池后的门控，而不是最终创世验证的替代。生产
顺序是：`mainnet:genesis:verify` 在干净的最终快照上通过，资金池启动后定价被冻结，受绑定的
储备注资方通过通知流程为销售方注资，然后 `market-stability:readiness` 检查销售方状态、注资、价格
证据和钱包背书。只有在该就绪检查通过之后，销售方就绪状态才具有生产有效性。

注资只在以下情况被接受：

- 封存之后；
- 定价冻结之后；
- 通过官方销售方 ATH 钱包；
- 来自受绑定的储备注资方；
- 直到 `60,000,000 ATH` 的总上限。

只有经过认证的储备注资才增加可售储备的会计。运行时允许部分储备注资和部分销售，但启动就绪要求完整储备：`reserve_due_ath == 60,000,000 ATH`、`reserve_funded_total_ath == 60,000,000 ATH`，以及至少 `60,000,000 ATH` 的官方钱包背书。向官方销售方 ATH 钱包进行的未经请求的普通 ATH 转账不会增加 `reserve_due_ath` 或 `reserve_funded_total_ath`，不会扩大可售供应，并且可能保持卡住状态。就绪检查将高于 `60,000,000 ATH` 的官方钱包余额视为一个警告，而不是额外储备。

该储备被拆分为 20 个批次：

```text
20 * 3,000,000 ATH = 60,000,000 ATH
```

每一批都有一个乘数：

```text
x2, x3, x4, ..., x21
```

这创造出一个平滑的价格阶梯。随着项目热度增长，市场获得额外的 ATH 供应，但每一个下一批都比前一批更贵。早期需求不会立即冲击一个薄弱的资金池，价格增长也不会变成一堵让这个实用型代币难以使用的垂直高墙。

购买公式：

```text
price = ceil(base_tranche_price * current_multiplier * amount / 3,000,000 ATH)
```

`base_tranche_price` 在资金池启动后被冻结，并与 x1 定价证据完全匹配。

在启动价格 `1 ATH = 0.001 GRAM` 下，一批的 x1 价格为：

```text
3,000,000 ATH * 0.001 GRAM = 3,000 GRAM
```

因此：

| 批次 | 乘数 | 3M ATH 的价格 | 每 1 ATH 的价格 |
| ---: | ---: | ---: | ---: |
| 1 | x2 | 6,000 GRAM | 0.002 GRAM |
| 2 | x3 | 9,000 GRAM | 0.003 GRAM |
| 3 | x4 | 12,000 GRAM | 0.004 GRAM |
| ... | ... | ... | ... |
| 15 | x16 | 48,000 GRAM | 0.016 GRAM |
| ... | ... | ... | ... |
| 20 | x21 | 63,000 GRAM | 0.021 GRAM |

单次购买不能跨越批次边界。这防止了以前一批的价格从下一批购买 ATH。

只有在 ATH 交付给买家之后，GRAM 收入才被确认。如果 ATH 转账失败或退回，储备被恢复，买家收回其支付的 GRAM 本金，并且国库待处理不增加。

在最后的 x21 批次售出之后，MarketStabilitySeller 不再调节 ATH 价格。从那一刻起，价格完全由市场决定：流动性、可用供应、对 `.ath` 名称的需求、头像更新、空投后的 Vault 协议费折扣，以及回购/销毁压力。

即便在 x21 步，相对于实用性模型，参考估值仍然温和：

```text
1 ATH = 0.021 GRAM
100,000,000 ATH = 2,100,000 GRAM
```

在 x21 步，MarketStabilitySeller 已完成其程序化的储备释放。此后，ATH 价格完全由市场决定，取决于流动性、使用需求、可用供应，以及回购/销毁压力。唯一剩余的协议分配是缓慢的长期归属计划，上限为每年 `100,000 ATH`。

## 国库与销毁分桶

UsernameRegistry 和 ProfileRegistry 使用相同的 ATH 费用拆分模型：

```text
accepted ATH fee -> 50% treasury_due_ath + 50% burn_due_ath
```

国库待处理的清算通过官方 ATH 钱包将 ATH 发送给国库接收方。

销毁待处理的清算通过官方 ATH 钱包发送一次 ATH 销毁请求。供应只有在 ATHMaster 中销毁最终确认之后才减少。

失败与退回路径会恢复待处理分桶。会计一直被保留，直到下游转账或销毁完成。

## ATHWallet 会计

ATH 余额存在于确定性的 ATHWallet 合约中。

ATHWallet 处理：

- 创世供应贷记；
- 普通转账；
- 带通知转账；
- 用户名铸造通知；
- 资料头像通知；
- 销毁请求；
- 通知确认；
- 陈旧通知裁剪；
- 退回/失败恢复。

接受 ATH 作为付款的合约不接受来自任意地址的直接消息。它们只接受来自其官方 ATHWallet 的通知。来源钱包认证在 ATHWallet 内部通过确定性的钱包派生执行。

ATH 为通用 jetton 工具暴露类 TEP-74 的转账入口点，但 Platho 协议操作使用经过认证的 ATH 通知消息。外部集成一定不能假定 Platho 的通知流程会发出通用的 `JettonTransferNotification`。

ATHWallet 中的出站内部转账受来源侧的待处理会计和来源确认保护。在没有待处理证明的情况下，余额不会从退回体中恢复。

## ATH 生命周期

1. `ATHMaster` 创建 `100,000,000 ATH` 的固定供应。
2. 国库一次性部署在国库 ATH 钱包中接收供应。
3. 供应被分配到活动、流动性、长期归属和市场稳定。
4. 用户通过 Vault 发布消息。
5. 一次成功发布计入 `10 ATH` 活动奖励。
6. 在全部 `15,000,000 ATH` 活动空投分发完毕且 `airdrop_remaining_ath == 0` 之后，ATH 协议费折扣解锁。
7. ATH/GRAM 资金池以参考价格 `1 ATH = 0.001 GRAM` 启动。
8. 资金池后的路由证据和定价证据被冻结。
9. MarketStabilitySeller 通过 x2..x21 批次出售储备。
10. 在拆分被启用之后，FeeAccumulator 在国库和回购之间划分协议 GRAM 费用。
11. BuybackBurn 用 GRAM 协议费购买 ATH，并通过 ATHMaster 销毁 ATH。
12. 用户名和资料费用创建 ATH 国库待处理和 ATH 销毁待处理。
13. 总供应量通过经过认证的销毁逐渐减少。

## 最终模型

ATH 连接 Platho 的四个层次：

1. **应用使用** —— 消息创造活动奖励。
2. **付费功能** —— 用户名和头像需要 ATH。
3. **折扣** —— ATH 余额在分发门控之后降低协议费。
4. **供应减少** —— 部分 ATH 费用和回购产出通过 ATHMaster 被销毁。

该模型始于固定供应和 `100,000 GRAM` 的参考估值。主要的用户分发与真实的付费使用绑定：产品文案可以表述为消息从 `0.0337 GRAM` 起，而当前确切的示例是 1 KiB 公开帖子为 `0.0337 GRAM`、混合私密 1 KiB 胶囊为 `0.0347 GRAM`，外加每个最终确定的胶囊 `10 ATH` 的活动奖金。更大的公开或私密尺寸类别成本更高。该奖金不是退款、报销或盈利承诺。在前 15% 的供应分发完毕之后，资金池启动，协议费折扣解锁，回购路径开启。

ATH 作为 Platho 内部一个可用的代币而存在：它通过活动分发，用于付费操作，降低协议费，通过一个明确定义的阶梯从储备中出售，并通过链上销毁被销毁。在市场稳定阶梯之后，未来的 ATH 价格由市场和协议使用决定。

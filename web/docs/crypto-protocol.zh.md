# Platho 加密机制

## 密钥与身份

一切都从同一组助记词派生：钱包密钥、签名密钥、加密密钥和扫描密钥。私钥部分从不离开你的设备——没有服务器知道它们，因为根本不存在服务器；网络也不知道。

上链的只有公钥部分，存放在你的 KeyShard 里。该分片的地址与你的钱包地址绑定，因此它只能保存这个钱包注册过的内容——地址绑定本身就是全部授权。分片保存四项：加密公钥、签名公钥、扫描公钥，以及密钥世代号。

密钥标识不是被分配的，而是**算出来的**：`keyId = H(加密公钥, ML-KEM 公钥的哈希)`。想冒用别人的 keyId，就得先拿到别人的加密密钥。

激活，就是首次把自己的公钥发布上链。费用 0.06 GRAM，从钱包支付。

## 首次联系

写给陌生人的第一封信无从引用共享秘密——此时还不存在。它走的是单独一条通道。

**收信人如何找到它。** 胶囊的公开部分只有 42 字节：一个随机点 `R` 和两字节的 `view_tag`。这个标记由 `R` 和收信人的**扫描**密钥算出。收信人逐条核对近期记录，用自己的密钥验证标记；旁观者只能看到随机字节，无法判断信是写给谁的。公开部分里根本没有收信人地址。

**收信人如何确认是谁在写。** 加密正文中包含一次握手：发信人对一份转录内容的签名，该转录绑定了双方的 keyId、发信人的静态加密公钥、其 ML-KEM 公钥的哈希、两个 KEM 密文、`R`、`view_tag` 以及一个一次性随机数。签名会在任何字段被采信**之前**完成验证——否则攻击者就能把别人的签名嫁接到自己的密钥材料上。

两项检查就够了，而且都不需要读链：

1. 用出示的公钥重新计算 `keyId`，必须与其声称的一致；
2. 确认标签证明发信人**推导出了同一个根密钥**，而这需要加密公钥背后的私钥。

第一项迫使伪造者使用受害者的密钥，第二项就在这里把他拦住：他推不出根密钥，标签对不上，信件被拒绝。

逐字节重放会被握手中的一次性随机数识破。

首次联系的记录在链上保留一周——足够被读取，不足以沉淀成档案。

## 已建立的会话

首次联系之后，双方共享一个根密钥，此后的往来全部走第二条通道，那里对参与者只字不提。

```
K_root  = HKDF( X25519(a,B) ‖ ML-KEM-768 共享秘密,  info = ROOT ‖ 较小的 keyId ‖ 较大的 keyId )
K_epoch = HKDF( K_root,  info = RATCHET ‖ 纪元编号 )
bucket  = HKDF( K_epoch, info = BUCKET ‖ 方向 ‖ 纪元编号 )
```

根密钥是混合的：经典 X25519 与一次真实的随机化 ML-KEM-768 封装同时参与其中。所谓抗量子强度正在于此——单靠一台针对 X25519 的量子计算机，攻不破这个根。

一个纪元为一个 UTC 日。会话的每个方向各自写入**专属的**不透明 `bucket`，只有知道根密钥的人才能算出它。胶囊的公开部分是 40 字节，里面只有这个 `bucket`：没有发信人，没有收信人，也没有指向上一条消息的引用。试图建立索引的观察者，看到的是均匀随机的 32 字节，无法与任何人对应起来。

## 胶囊

正文采用 X25519 与 ML-KEM-768 的混合加密，外层是认证加密。发信人的身份（签名公钥、资料版本、头像指纹）位于密文**内部**，而不在公开部分。

胶囊有固定的尺寸档位，从 1 KB 到 32 KB。尺寸向上取整，因此记录的长度说明不了消息的长度。超出的内容会拆成多个胶囊。

## 公开信息流

公开帖子和评论**不加密**——这正是它们的用途。它们以明文存放在 PublicShard 中，合约把交易的发送方视为作者，因此作者的钱包地址是公开可见的。

评论存放在另一个分片，其地址由帖子的坐标推导得出。

## 支付

不存在中间人：客户端自己签署外部消息，并从自己的钱包付款。没有中继方，没有内部余额，也没有哪个可信第三方能拒绝你发布。

协议费为每个胶囊 0.01 GRAM，首次联系与会话同价。发布价格的其余部分，是网络收取的燃料费与存储费。

## 恢复

会话密钥保存在设备上，加密它的密钥从不离开设备。这足以熬过一次刷新，却在重装后失效，所以还有第二份副本：根密钥表以**从助记词派生的密钥**封存，放入你在 RecoveryShard 中的槽位。一台只有助记词的新设备能找到该槽位，读取并解密——会话就回来了。

槽位里只放那些无法重新推导的内容。

## 受保护的与可见的

一份诚实的清单——没有它，任何承诺都不值几分。

**受保护：**

- 私人通信的内容：只有你和对方能读；
- 私人消息的收件对象：收信人由隐形寻址和不透明的 `bucket` 掩护；
- 「谁与谁通信」的关系图：没有根密钥，两个方向无法彼此关联。

**所有人可见：**

- 某个钱包发布过一个私密胶囊、发布时间，以及尺寸档位；
- 一切公开内容——文字、图片、评论，以及作者的钱包地址。

## 链上留存期限

| 内容 | 期限 |
|---|---|
| 首次联系 | 1 周 |
| 私人通信 | 1 年 |
| 公开帖子与评论 | 1 年 |

期限届满后，记录会被清出所在分片。而发布它的那笔交易将无限期留在链的历史中：在区块链上删除数据是不可能的。
